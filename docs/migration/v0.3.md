# v0.2 to v0.3 migration

The graph schema is a breaking execution API change. Original state and credentials remain intact. v0.2 approvals and remote session IDs do not authorize or resume v0.3 work.

```bash
ralph migrate --to 0.3 --dry-run
ralph migrate --to 0.3
```

The migration manifest classifies completed records as read-only history and interrupted records as requiring a new plan. It backs up the config, legacy run directories and referenced contracts under the Git-internal `migration/v0.3/<digest>` directory. Repeated migration with unchanged input uses the same manifest identity. Connection IDs, credential references, route policies/Hard Pins and verification settings are preserved. Original records are never automatically deleted.

For an interrupted old run:

1. Inspect `ralph history` and the preserved worktree, checkpoint and evidence.
2. Use the existing `ralph recover` procedure if an old process or dirty working tree needs attention. Do not discard user edits.
3. Ensure the intended current project baseline is clean.
4. Generate a new plan linked by `originRunId`:

```bash
ralph plan --from-run <legacy-run-id> --json
ralph run --plan <new-run-id> --yes
```

Review the new contract, graph and budget before the second command. The new plan revalidates all criteria against the current baseline; it does not blindly import partially edited files or reuse provider sessions. A still-running legacy record must be recovered first.

## Integration changes

| Old API or command | v0.3 |
|---|---|
| draftContract | planRun (draft remains a compatibility helper) |
| executeContract with v0.2 approval | planRun → review → approvePlan → startRun |
| resumeRun returning RunState | resumeRun(projectRoot, runId) returning GraphRunState |
| run --contract-stdin --yes | run --plan-stdin --yes after reviewing that plan |
| loop-level snapshots | run + revision + node generation + event seq |

Host integrations use the same public CLI/schema. The Bash migration command without `--to` remains a separate legacy path. Existing history is readable; graph features are not added to the old Bash runner.
